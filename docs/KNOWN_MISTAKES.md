# DentVideo known mistakes

Every mistake we have seen in a DentVideo video, written down, with the check that now stops it.

**The rule:** when a new mistake is found in a render (a contact sheet, a sample, a clinic's feedback), it gets a row here and a check before the next release. Usually the check goes in `worker/src/dental/known-mistakes.ts`, or in the check that already owns that class of mistake. The check also gets a regression test that uses the exact text that was seen. Nothing that a pattern can see reaches a clinic twice.

## How a check stops a video

- `week.ts scriptProblems` runs on every draft before any paid reviewer. It runs every rule in `known-mistakes.ts` over the hook, the on-screen lines and the narration. `captionProblems` does the same for the caption. A hit goes back to the writer as a fix, for example `screen: "Avoid strong colors briefly" — …; "skip dark drinks…" (known mistake KM-13)`. If a draft still fails after three attempts, the topic is rejected (`status: "rejected"`). It is never published as it is.
- `style.ts hookProblems` also treats a clickbait hook as a blocking problem. The hook editor never picks one, and the post-check sends one back.
- Some fixes are made in code instead of being sent back: `withoutReflexiveNotQuite` and `dropEchoes` in `week.ts`, and the narrator's single less-hedged edit (`lessHedged`).
- `scripts/sync-hard-rules.mjs` copies `known-mistakes.ts` into `web/src/lib/dentvid/known-mistakes.ts`. `web/src/lib/dentvid/known-mistakes.test.ts` runs it over every live preview plan (all languages) and every examples page. A known mistake on the site fails the web tests unless the sample appears in that test's `LIVE_FLAWS` list, and every entry there is a row below marked *live*.
- `worker/src/dental/fixtures/published-samples.json` holds the text of every published sample's render plan and every discarded render. `known-mistakes.test.ts` checks that:
  - every published sample passes the whole post-check, apart from the live flaws listed here;
  - every discarded render is sent back.

**False positives.** The rules were run over all 18 published samples, all 30 baseline scripts, the 6 reference scripts, the 10-language hook bank, every live preview plan and every examples page. They flag only the known-bad text. One false positive turned up while the rules were being written: the French hook bank's "Ce petit pincement quand vous buvez froid…" matched the bare-noun rule. The rule now skips the indicative after "vous" and adverbial adjectives ("buvez froid"). Both cases are pinned in the tests.

Status values:
- **caught (new):** a check added with this register.
- **caught:** an earlier check, now pinned with the verbatim text.
- **repaired:** code fixes the mistake instead of sending it back.
- **reviewer only:** no pattern can see it; the LLM reviewers and the contact-sheet review catch it.
- **live:** a published sample still has the mistake.
